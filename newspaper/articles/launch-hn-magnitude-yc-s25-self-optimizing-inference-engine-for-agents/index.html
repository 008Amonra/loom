Magnitude: An Inference Engine That Tunes Itself to Your Hardware

Magnitude is a new open-source inference engine for local AI agents, released by a two-person team from Y Combinator’s S25 batch. It ships as a desktop app, runs models on Mac, Linux and Windows, and - according to its own benchmarks - is up to twice as fast as llama.cpp on the same hardware.

The team posted their launch on Hacker News (https://news.ycombinator.com/item?id=49911995), where it has since collected 194 points and nearly 100 comments. The discussion has been unusually candid: several users reported the numbers do not hold on every machine, and the founders have answered those reports directly in the thread.

Who is actually behind it

The launch post is signed “Anders and Tom”. Both are software engineers who previously built an open-source browser agent that they say reached more than 4,000 GitHub stars and 100,000 downloads.

In their words: “We increasingly wanted to run it on local models, but found that no inference engine worked for our use case.”

That gap - running long-lived, concurrent agent sessions on a normal desktop while keeping the machine usable - is the problem Magnitude is aimed at.

The core idea: tune on the machine, not in the lab

Most inference engines make a fixed performance trade-off. As the founders put it: “Inference engines today all make a performance tradeoff.” Batched datacenter engines such as vLLM and SGLang optimise for throughput at the cost of single-session speed. Broadly compatible engines such as llama.cpp and Ollama optimise for portability. Specialised engines trade completeness for raw speed on one hardware target.

Magnitude takes a different route in four steps:

  • On-device compilation and tuning. Kernels are written with flexible parameters, then tuned against the actual machine before the model runs. The claim is hardware-specific performance without hardware-specific code.
  • Focus on popular open-weight families. Rather than generalising to every architecture, the team writes highly efficient kernels for a small number of widely used model families.
  • Dynamic memory allocation. Only the model weights are reserved up front; the memory heap grows as agent sessions grow and shrinks when they stop.
  • Hybrid paged attention. Borrowing from SGLang’s radix attention, concurrent sessions share prefix caches, but placement is optimised for memory adjacency so single-session performance does not regress.

The engine is written in Rust, includes a custom GPU kernel runtime and autotuner, and is released under Apache 2.0. The team cites FlashAttention, FlashInfer, TurboQuant and SGLang as design inputs.

What the benchmarks actually say

Measured against llama.cpp using Qwen 3.6 35B A3B at 4-bit, 64k context and no speculative decoding:

Hardware Decode Prefill Per-agent memory
Metal (Mac M4 Pro, 48 GB) 92% faster (30 → 57 tok/s) 9% faster (466 → 507 tok/s) 28% less
CUDA (DGX Spark) 19% faster (49 → 58 tok/s) 23% faster (2,033 → 2,507 tok/s) 27% less

The team has published the benchmark source: a prose-repetition task that fills the context with Moby Dick and asks the model to repeat the last section, run against llama.cpp with comparable settings, flash attention on and speculative decoding off.

Two further details from the thread: tuning is a one-time step of roughly one minute per model download, and the KV cache is quantised to 8-bit keys and 4-bit values using a TurboQuant-inspired scheme, which the team says more than halves KV memory without degrading long-context retrieval in their RULER-based evaluation.

Where it does not hold up

The comment thread is not a rubber stamp.

Several testers on M5-generation Macs reported Magnitude slower than the alternatives. One benchmark on an M5 Max put rapid-mlx at 175 tok/s against Magnitude’s 161 tok/s, with a slower time-to-first-token as well. The founders attribute this to a known gap: their kernels do not yet use the Metal 4 matmul operations available on M5 and newer silicon, and they say a fix is coming.

Other open issues raised in the thread include no multi-GPU support (acknowledged as near-term roadmap work), no ROCm backend (Vulkan is used for AMD hardware for now), and model-download assessment that hung for some users.

An independent test on a 5080 GPU reported Magnitude slower than llama.cpp at decode for a Gemma model.

Beyond speed: what is on the roadmap

Three items are named: expert streaming, which stores mixture-of-experts weights on RAM or disk and loads them just in time; a kernel compiler that chooses how to fuse kernels rather than tuning a handful of parameters; and multi-device utilisation, detecting every CPU, GPU, RAM and disk on a system and solving for the best model layout across them.

On business model, the founders say they plan to charge per token for an inference cloud aimed at hybrid workloads - local models for everyday tasks, cloud models for harder ones - while keeping the local engine free.

A credible claim, carefully stated

Magnitude is not a self-improving AI and the launch post does not claim one. It is a fast, self-tuning inference engine with published numbers, an Apache 2.0 licence and a team answering difficult questions in public. Whether the headline speed-ups survive contact with hardware outside the tested set is exactly what the Hacker News thread is currently working out - and, to their credit, the founders are answering.
