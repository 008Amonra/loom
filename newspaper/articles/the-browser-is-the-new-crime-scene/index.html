The Browser Is the New Crime Scene

Claude for Chrome sat unpatched for 54 days. The security perimeter moved into your tab, and nobody noticed.

There’s an old rule in the private eye business: you don’t follow the mark into his own home. That’s where he knows every creak of the floorboards, every shadow in the hallway, every exit that doesn’t show up on the blueprints.

In July 2026, someone followed Claude into your browser - and your browser, the one you trust with your email, your calendar, your documents, your entire digital life, rolled out the red carpet and let the intruder walk straight in.

The call came in from a two-person shop called Manifold Security. Their researcher, Ax Sharma, had been knocking on Anthropic’s door since May 21st with a report about two unpatched flaws in Claude for Chrome. By July 14th - eight patch releases later, versions 1.0.72 through 1.0.80 - the vulnerable code was still there, byte for byte identical. Anthropic had acknowledged the report the next day, then closed both findings. One was folded into an existing tracker. The other was marked “informative.” Neither was fixed.

The first flaw is elegant in its simplicity. Claude’s content script listens for clicks on a specific onboarding button, reads its data-task-id, and if it matches one of nine hardcoded tasks, fires an open_side_panel message to the extension. The handler never checks event.isTrusted - the browser flag that distinguishes a real human click from a synthetic one dispatched by a script. Any other extension with script access on claude.ai can forge the click. Manifold demonstrated it with six lines of JavaScript. The forged click works on Opus. It works on Sonnet. It works on Fable too. The bug is in the extension, not the model.

Nine hardcoded tasks await behind that click. Three are onboarding exercises. Three are partnerships - DoorDash, Salesforce, Zillow. The last three are the ones that matter: usecase-gmail, usecase-gdocs, usecase-calendar. Claude reads your mail. Claude opens your latest Google Doc and reads every comment. Claude scans your calendar and creates meetings. In default mode, an approval box still stands between the forged click and the actual read - CVSS 7.7 High, per Manifold’s scoring. But if a user has enabled “Act without asking,” the hands-off automation mode, the action runs with no prompt at all. That’s CVSS 9.6 Critical.

The second flaw is quieter, but it’s the one that keeps you up at night. When Claude’s side panel loads with ?skipPermissions=true in its URL, it boots directly into skip_all_permission_checks. No gesture. No consent screen. A red warning banner appears - but only after the privileged session is already running, a notice, not a gate. The parameter is only set internally today. The fix is simple: stop reading permission mode from the URL, boot the panel in ask mode every time. It hasn’t shipped.

This wasn’t the first time. In March, Koi Security researcher Oren Yomtov disclosed ShadowPrompt - a zero-click XSS prompt injection chain that exposed over three million users. The attack chained two flaws: an overly permissive *.claude.ai origin allowlist that accepted prompts from any matching subdomain, and a DOM-based XSS vulnerability in an Arkose Labs CAPTCHA component hosted on a-cdn.claude.ai. An attacker could embed the vulnerable component in a hidden iframe on any malicious webpage. The victim sees nothing. The page loads. The CAPTCHA renders the injected JavaScript. The script fires a prompt to the extension through chrome.runtime.sendMessage(). The extension sees a trusted origin. Claude executes the instruction. No clicks. No permission dialogs. No visible indicators.

In April, LayerX Security found ClaudeBleed - a confused-deputy problem where the extension trusted the claude.ai origin instead of verifying which script was actually talking to it. A zero-permission extension could drive Claude’s browser agent capabilities. Anthropic patched the arbitrary-prompt path, boxing external callers into the nine fixed task IDs. That was the improvement that Manifold later showed still had no guard on the trigger.

In June, LayerX published BioShocking - an indirect prompt injection technique that compromised six AI browsers and extensions, including Claude. The attack didn’t exploit a software bug in the conventional sense. It traveled entirely through the model’s reasoning. A researcher-controlled webpage presented the agent with a casual game in which correct answers were declared wrong and incorrect answers were rewarded. Once the agent accepted a false operating premise - a form of reality distortion - its standard safety refusals ceased to engage. The agent, operating within an already-authenticated browser session, could reach any resource the user was logged into: banking portals, corporate identity providers, SaaS applications. Cloud Security Alliance researchers classified the underlying architecture as the “lethal trifecta” - access to private authenticated data, exposure to untrusted external content, and an exfiltration pathway via the agent’s own network-capable actions. Each element is present by design.

The numbers tell the rest. Prompt injection attacks surged 340% in 2026, making them the single fastest-growing category of cyberattack globally, according to Techglock’s analysis. OWASP ranks prompt injection as the number one AI threat. Eighty-seven percent of CISOs cite AI agent security as a top concern. Only eleven percent have safeguards in place.

And the timeline is damning. Manifold reported the two flaws on May 21st against v1.0.72. Anthropic acknowledged the next day. The company’s internal tracking issue was marked “Resolved” before June 9th. Between May 21st and Manifold’s July 14th public disclosure, Anthropic released eight versions of the extension. None addressed the flaws. As of publication, no CVE had been assigned for either issue, and Anthropic had not issued a public response.

“AI browser extensions that read and process page content are a new class of attack target,” the Bellator Cyber Guard security team wrote. “That same capability - ingesting arbitrary web content and acting on it - is precisely what makes them exploitable.”

The architecture tells you everything you need to know. When AI agents can read your browser, your browser becomes the attack surface. The security perimeter is only as strong as the weakest trusted origin. Third-party vendor components hosted on first-party subdomains silently expand that trust boundary in ways that aren’t immediately obvious. As AI assistants gain deeper browser access, attackers gain higher-value targets, and supply chain trust issues become exploitable attack surfaces.

Perplexity’s BrowseSafe research, published July 17th, confirmed the scope: browser agents can see what users see, click what users click, and act across authenticated sessions in email, banking, and enterprise apps. Existing agent benchmarks fall short because they use short, straightforward injections - a single line of adversarial text - rather than the messy, high-entropy pages, feeds, comments, and UI chrome that real browser agents must parse. Detection systems must run asynchronously alongside the agent’s normal execution without blocking the user’s workflow. Small models like PromptGuard-2 struggle with real-world web complexity, achieving F1 scores around 0.35.

Meanwhile, the fix for the original ShadowPrompt chain was clean. Anthropic replaced the wildcard allowlist with a strict origin check requiring exactly https://claude.ai. The Arkose Labs XSS was separately patched, the vulnerable URL now returning a 403. Users who updated to v1.0.41 were protected. But the pattern - disclose, acknowledge, close, ship eight more versions with the same vulnerable code - is the pattern that haunts the story.

Oasis Security researchers, in their own March technical report, described a complete attack pipeline chained from three Claude.ai vulnerabilities: invisible URL-based prompt injection, data exfiltration through Anthropic’s own Files API, and an open redirect on claude.com to bypass security controls. The chain worked on a bare-bones Claude session. Zero integrations. Zero tools. Zero MCP servers. If you used Claude, you were exposed - not because of a plugin or an integration, but because of how the platform’s default capabilities interact.

The lesson is written in every one of these disclosures, in every unfixed byte of code, in every CVSS score that climbs past 9.0. The browser was never designed to be an AI agent’s home. We moved the agent in anyway, gave it the keys to our authenticated sessions, our email, our documents, our calendars - and then asked the browser’s existing trust model to protect us. It didn’t. It can’t. The trust model was built for a world where the only thing reading the page was a human eyeball.

When AI agents can read your browser, your browser becomes the attack surface. And the attack surface is always larger than the defenders expect it to be.
