Dead Link Embalmer

Link rot does not just break footnotes. It quietly rewrites public history.

A dead link looks harmless. One click fails, a browser shows an error, and the reader moves on.

But enough dead links can change the record. A report loses its evidence. A promise disappears from a company page. A public agency quietly replaces a document. A forum thread that explained the real fix becomes a blank page, a redirect, or a domain parking ad.

The Dead Link Embalmer is a small machine for that moment. It watches important URLs and preserves them when they fail, redirect, or meaningfully change.

Not every page deserves a monument. But some pages deserve a witness.

What It Watches

The machine starts with a list of URLs worth protecting:

  • citations in articles and reports
  • official policy pages
  • public procurement notices
  • tool documentation
  • small project pages
  • disappearing community knowledge
  • pages that have already changed once

It does not crawl the whole internet. That would be noisy, expensive, and mostly useless. It watches a chosen shelf.

What Counts As Trouble

A normal uptime checker only asks whether a page responds. The embalmer asks a better question: did the meaning survive?

Trouble can mean:

  • the page returns 404, 410, or repeated server errors
  • the URL redirects somewhere unrelated
  • the title, body text, or key links changed sharply
  • a PDF was replaced
  • a page became a login wall
  • the domain changed hands
  • the page still loads but the useful part vanished

That last case matters. Link rot is not always a dead page. Sometimes the corpse is still standing.

What It Saves

When a watched page crosses the threshold, the machine saves evidence:

  • raw HTML
  • readable text extraction
  • screenshot
  • PDF print
  • response headers
  • timestamp
  • final redirected URL
  • hash of the captured content

The hash is important. It gives the archive a fingerprint. Later, if someone asks whether the saved page changed, the machine can answer without drama.

Why It Is Useful

This is not only for historians. It is for anyone who cites the web and wants the citation to survive longer than the mood of a server.

Journalists can preserve sources. Researchers can protect references. Small project maintainers can keep old documentation reachable. Local watchdogs can notice when public information moves without announcement.

The machine does not decide what a change means. It records that the change happened.

Practicality

The first version is not expensive. A simple implementation can run on a schedule, read a list of URLs, compare current content with the last known version, and write captures to disk or object storage.

The hard part is judgment:

  • Which pages deserve watching?
  • How much change is meaningful?
  • How long should captures be kept?
  • Who is allowed to publish a saved copy?
  • When should the machine stay quiet?

Those questions are editorial, not technical. The machine can help, but it should not become a careless republishing engine.

Verdict

  • Practicality: high
  • Cost: low
  • Preservation value: high

The Dead Link Embalmer is useful because it is narrow. It does one newspaper-shaped job: keep receipts before the web forgets where it put them.
