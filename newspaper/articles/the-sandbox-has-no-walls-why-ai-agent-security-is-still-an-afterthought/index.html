The Sandbox Has No Walls: Why AI Agent Security Is Still an Afterthought

AI agents are everywhere. The walls around them are not.

The walls are missing. That is the problem.

Every major AI lab is shipping agents. Browser extensions that can read your email. Coding assistants that can execute arbitrary commands. Chat interfaces that can browse the web, fill out forms, and make purchases on your behalf. The capabilities are real, the demos are impressive, and the security model is, in most cases, an afterthought.

The Sandbox That Wasn’t

A sandbox is a restricted environment where code runs without access to the outside world. The concept is simple: you give the untrusted code a box, and you do not let it out of the box. The problem with AI agents is that the box is the product. The agent’s value comes from its ability to interact with the world. A sandboxed agent is a useless agent.

This creates a fundamental tension. The more capable the agent, the less sandboxed it must be. The less sandboxed it is, the more damage it can do. The industry has chosen capability over security, and the consequences are beginning to show.

The Browser Extension Problem

The most visible example is the browser extension market. AI agent extensions - the kind that can read web pages, fill out forms, and interact with websites - have exploded in popularity. The problem is that these extensions run with full access to your browser. They can read your email, access your banking, and interact with any website you visit.

The attack surface is obvious: if an attacker can inject a prompt into a web page that the agent visits, the agent will execute it. This is not a theoretical vulnerability. It has been demonstrated repeatedly, and the browser extension marketplaces have been slow to respond.

The pattern is consistent:

  1. AI agent extension launches with impressive capabilities
  2. Security researchers demonstrate prompt injection attacks
  3. The vendor issues a patch
  4. The patch introduces new vulnerabilities
  5. The cycle repeats

The root cause is that browser extensions were not designed for AI agents. They were designed for simple, static functionality. The security model assumes that the extension’s behavior is predictable and deterministic. AI agents are neither.

The Coding Assistant Crisis

The coding assistant market is equally troubled. Tools that can write code, execute commands, and modify files are being deployed with minimal sandboxing. The justification is always the same: the agent needs full access to be useful.

The incidents are piling up. In July, a coding assistant executed a rm -rf / command that deleted a user’s entire home directory. In August, another assistant was tricked into executing a reverse shell that gave an attacker remote access to the user’s machine. These are not edge cases. They are the predictable consequence of running untrusted code with full system access.

The technical community has been raising alarms for months. The Cato Institute’s recent paper on AI agent security identified over 200 incidents in the first half of 2026 alone. The trend is accelerating, not decelerating.

Why Security Lags Behind Capability

The reason is simple: security is a cost center, not a feature. It does not improve the demo. It does not increase the capability. It adds friction, reduces performance, and complicates the user experience. In a competitive market where every vendor is racing to ship the most capable agent, security is the first thing to be cut.

The incentives are misaligned. The vendor ships the agent. The user runs the agent. The damage from a security incident falls on the user, not the vendor. The vendor captures the value of capability; the user bears the cost of insecurity. This is a classic externality, and the market is responding exactly as you would expect: by underinvesting in security.

What Would Actual Security Look Like

The solutions are not mysterious. They are well-understood principles that have been applied in other contexts:

Principle of Least Privilege: Give the agent only the permissions it needs, not all the permissions it could use. A coding assistant that needs to read files does not need to execute arbitrary commands. A browser extension that needs to read web pages does not need to access your email.

Capability-Based Security: Instead of restricting what the agent cannot do, explicitly define what it can do. Every action requires a specific capability token. No token, no action.

Human-in-the-Loop: For high-risk operations (deleting files, sending emails, making purchases), require explicit human approval. This adds friction, but friction is the point. Security should be inconvenient.

Audit Logging: Record every action the agent takes. Not for debugging. For accountability. When something goes wrong, you need to know what happened.

Sandboxed Execution: Run the agent in a restricted environment with limited access to the system. Containers, virtual machines, and permission-restricted user accounts are not new technology. They are just not being used.

The Regulatory Landscape

Governments are beginning to notice. The EU’s AI Act, which took effect in January, includes specific provisions for AI agent security. The US is considering similar legislation. The direction is clear: mandatory security requirements for AI agents are coming.

The question is whether the industry will self-regulate or be regulated. The track record suggests the latter. The browser extension market has been insecure for years, and the marketplaces have done little to address it. The coding assistant market has been even worse, with vendors actively marketing the lack of restrictions as a feature.

What You Can Do

If you are using AI agents today, here is what you can do:

  1. Run agents in a sandbox: Use containers, VMs, or restricted user accounts. Never run an agent with root privileges.
  2. Limit capabilities: Use tools like AppArmor, SELinux, or firejail to restrict what the agent can access.
  3. Monitor activity: Log every action. Review logs regularly. Set up alerts for unusual behavior.
  4. Use reputable vendors: Prefer vendors who take security seriously. Ask about their security practices before deploying.
  5. Stay informed: Follow security researchers who cover AI agent security. The landscape is changing rapidly.

The Bottom Line

AI agents are powerful tools. They are also powerful attack vectors. The industry is prioritizing capability over security, and the consequences are predictable. The sandbox has no walls because the walls would reduce the capability. The capability is the product. The security is an externality.

This will change. Either the industry will self-regulate, or governments will regulate it. The question is how much damage will be done in the meantime.
