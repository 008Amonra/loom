Micro-API Librarian: The Long Tail of Public Data Vanishes Quietly

Deep in the municipal domain there is a JSON endpoint that one person set up in 2019 with a grant and a good intention. It feeds transit timetables, sensor readings, or the city’s tree inventory. Nobody else touches it. When the person leaves, the domain lapses, and the data set simply stops existing.

A Micro-API Librarian does the unglamorous job of keeping that data alive by snapshotting it before it disappears.

The Routine

  1. Monitor. Watch small civic endpoints: municipal JSON, transit feeds, sensor data, council datasets.
  2. Validate. Check the schema, not just the HTTP status. A 200 with an empty body is still a failure.
  3. Snap. Store last-known-good versions with metadata: purpose, cadence, field changes.
  4. Document. Keep the smallest useful description - who publishes it, on what schedule, what changed.

What It Reveals

  • Data disappears from neglect, not from malice. Expired domains, vendor switches, staffing gaps, deprecated links.
  • Schema drift. A field renames, a unit changes from meters to feet, and downstream consumers silently compute garbage.
  • The invisible caretaker. The public notices the endpoint the day it stops working, and only then.

The Argument

Nobody will fund the librarian because it prevents something nobody can see. But a newspaper that ran a Micro-API Librarian for a year would have the receipts when the city deletes the dataset it promised to keep. The machine makes silence visible.
